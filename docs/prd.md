# YakuMado 要件定義書(PRD)

## 0. 位置づけ

本ドキュメントは `docs/tech-research-screen-translation.md`(deep-research + 一次ソース追加検証 全7項目済み、最終コミット `2146476`)を土台に、YakuMadoの要件を定義するものです。現時点でリポジトリに実装コードは存在せず、本PRDはゼロからの開発を前提とします。

対象読者: 実装フェーズを担当する開発者(自分自身を含む)。

## 1. 背景・目的

Windows上で、Webブラウザや各種アプリケーション画面に表示された英語テキストを日本語に翻訳するデスクトップソフトウェアを開発する。

- **絶対要件**: 選択したテキストを日本語に翻訳できること
- **最重要目的**: 翻訳の高速性

## 2. MVPスコープ

ユーザー確認済み: **選択テキスト翻訳と画面オーバーレイ翻訳の両方をMVPに含める**(段階的リリースにせず、最初から両機能を実装する)。

## 3. 機能要件

| ID | 要件 | 詳細 |
|----|------|------|
| F1 | 選択テキスト翻訳 | ユーザーが任意アプリ上でテキストを選択し、ホットキー操作で翻訳結果をポップアップ表示する |
| F2 | 画面オーバーレイ翻訳 | 画面上の英語テキスト領域を検出し、原文の上(または付近)に日本語訳をオーバーレイ表示する |
| F3 | 選択テキスト取得の3段階フォールバック | ①UI Automation `TextPattern.GetSelection`(高速だが非対応コントロールで例外) → ②クリップボード方式(`Ctrl+C`送出→読取→復元、主軸) → ③範囲指定OCR(最終フォールバック) |
| F4 | 翻訳エンジン抽象化 | `ITranslator` インターフェースにより、ローカルNMT/クラウドAPIを実装差し替え可能にする |
| F5 | 翻訳結果キャッシュ | 同一テキストの再翻訳を回避するLRUキャッシュ(正規化キーで一致判定) |
| F6 | 設定UI | 翻訳エンジンの優先順位、有効/無効、APIキー入力 |
| F7 | APIキー管理 | クラウド翻訳APIキーをDPAPIで暗号化して保存 |
| F8 | 常駐トレイアイコン | バックグラウンド常駐、トレイメニューから設定・終了操作 |
| F9 | 対応言語表示 | 現在利用可能な翻訳エンジンと対応言語ペアをUI上で確認可能にする |
| F10 | エラー通知 | 翻訳失敗・API障害時にユーザーへ非侵襲的に通知する |

## 4. 非機能要件

| 区分 | 要件 | 備考 |
|------|------|------|
| 速度(選択テキスト翻訳) | 300ms以内 | ストレッチ目標: 100ms以内。目標値は暫定であり実測により調整する |
| 速度(画面オーバーレイ翻訳) | 800ms以内、再出現時50ms以内 | ストレッチ目標: 500ms以内。再出現時とは同一画面内容の再翻訳を指す(キャッシュ活用が前提) |
| リソース | 常駐メモリ150MB以下 | アイドル時CPU使用率は極力低く抑える(具体的な数値目標は実測ベースで設定) |
| 対応OS | Windows 10 1803(build 17134)以降 | Windows.Media.Ocr.OcrEngineはWindows 10.0.10240.0(初期ビルド)から利用可能と一次ソースで確認済みのため、より広い対応も検討余地あり |
| OCR精度 | 95%以上(仮目標) | 実測ベンチマークで再設定する |
| オフライン動作 | 許容 | ローカル翻訳エンジンのみで動作可能な構成を維持する |
| 可用性 | クラウド障害時はローカルへフォールバック(またはその逆) | `IsAvailable` による自己申告方式のフォールバック |
| セキュリティ | クリップボード内容の確実な復元 | 選択テキスト取得(F3)でクリップボードを一時利用する際、必ず元の内容を復元する |
| セキュリティ | APIキーの安全な保管 | 環境変数またはDPAPI暗号化ストレージを使用し、平文でのハードコード・ログ出力を禁止する |

## 5. スコープ外(MVP時点)

- 英日以外の多言語対応
- ユーザー定義用語集機能
- 動画字幕翻訳
- 音声翻訳
- プロセスフック方式によるテキスト取得(DirectWriteアプリ非対応の問題があるため見送り)
- Windows App SDK Text Recognition API(NPU搭載機=Copilot+ PC専用と一次ソースで確認済みのため対象外)
- 自動アップデート機能
- 課金・ライセンス機能
- マルチモニタ環境での完全な座標精度保証
- 翻訳モデルの自前学習・ファインチューニング

## 6. 未解決の重要課題

- **英→日ローカルNMTモデルの実用性が未確認**: Sugoi-v4は日→英専用モデルであり英→日には不適合と一次ソースで確認済み。Bergamotの高速化数値(47倍小型・37倍高速)はen-pt言語ペア限定でありen-jaでの効果は未検証。→ Phase 0のPoC②で実用性を検証し、結果次第でPhase 4のスコープを調整する(詳細は `docs/architecture.md` 参照)。
